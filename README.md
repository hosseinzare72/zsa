## نصب و فعال‌سازی

1. فایل `zsa-portfolio-manager.zip` را از **افزونه‌ها ← افزودن ← بارگذاری افزونه** نصب کنید (یا پوشه را در `/wp-content/plugins/` آپلود کنید).
2. **فعال‌سازی** را بزنید. ترم‌های «نوع پروژه» و تنظیمات پیش‌فرض ساخته می‌شوند.
3. **تنظیمات ← پیوندهای یکتا** را باز کنید و فقط یک‌بار «ذخیره تغییرات» بزنید (برای فعال شدن آدرس‌های `/project/...`).
4. از منوی **پورتفولیو ZSA ← تنظیمات ← تب ابزارها** روی **اجرای مهاجرت اولیه** کلیک کنید. ۲۰ پروژه ساخته می‌شود (اگر قبلاً ساخته شده باشند، دوباره ساخته نمی‌شوند و فقط فیلدهای خالیِ نسخه جدید تکمیل می‌شود).
   - مهاجرت تصاویر را از آدرس‌های سایت خودتان دانلود می‌کند؛ اگر سایت به اینترنت دسترسی خروجی نداشت، تصویر را دستی در هر پروژه («تصویر پروژه») بگذارید.
5. در تب **عمومی** این‌ها را بررسی کنید: شماره تماس کردیت، لینک تلگرام، **آدرس صفحه پورتفولیو** (پیش‌فرض `/zsa-studio/`).

## تمام‌صفحه کردن برگهٔ پورتفولیو (مهم‌ترین بخش)

هدف: برگه‌ای که فقط نمونه‌کارها را نشان می‌دهد — بدون هدر سایت، فوتر، سایدبار، مسیر صفحه، دیدگاه‌ها و هر چیز مزاحم دیگر. سه راه دارد؛ **راه اول بهترین است**.

### راه ۱ — قالب برگهٔ اختصاصی (پیشنهادی)

1. برگهٔ پورتفولیو را در ویرایشگر باز کنید.
2. در ستون سمت چپ، بخش **برگه (ویژگی‌های برگه)** را باز کنید.
   - اگر این بخش را نمی‌بینید: روی سه‌نقطهٔ بالا چپ → «تنظیمات/Preferences» → زبانهٔ «عمومی» → «بخش‌های اضافی» را فعال کنید، یا از «نمایش ← ویژگی‌های برگه» قدیمی استفاده کنید.
3. در فهرست **قالب**، گزینهٔ **«ZSA — تمام‌صفحه (بدون هدر/فوتر)»** را انتخاب کنید.
4. برگه را به‌روزرسانی کنید.

در این حالت افزونه یک سند HTML کامل و تمیز می‌سازد (`templates/full-page.php`) و قالب سایت اصلاً دخالتی ندارد: فقط محتوای برگه چاپ می‌شود، همراه با یک لینک «پرش به محتوای اصلی» برای دسترسی‌پذیری.

### راه ۲ — حالت سازگار با CSS (برای صفحه‌سازها و قالب‌های FSE)

اگر نمی‌توانید قالب برگه را عوض کنید:

- **پورتفولیو ZSA ← تنظیمات ← تب «تمام‌صفحه» → «حذف هدر/فوتر قالب با CSS»** را فعال کنید، **یا**
- در شورت‌کد بنویسید: `[zsa_portfolio fullpage="1"]`، **یا**
- در بلوک گوتنبرگ، حالت «صفحهٔ کامل» را انتخاب و گزینهٔ «تمام‌صفحه» را روشن کنید.

این حالت کلاس `zsa-pm-chrome-off` را به `<body>` اضافه می‌کند و با CSS هدر، فوتر، سایدبار، مسیر صفحه، تیتر/فوتر نوشته و بخش دیدگاه‌های قالب را پنهان می‌کند و حاشیه‌های کانتینر را صفر می‌کند.

### راه ۳ — تنظیمات تکمیلی در تب «تمام‌صفحه»

| گزینه | کاربرد |
|---|---|
| تم تمام‌صفحه | روشن یا تاریک؛ رنگ پس‌زمینه و متنِ کل برگه را تعیین می‌کند (`full_theme`) |
| حذف هدر/فوتر قالب با CSS | راه ۲ را همیشه فعال می‌کند |
| مخفی‌کردن نوار مدیریت | نوار بالای وردپرس را در این برگه مخفی می‌کند |
| بارگذاری همیشگی فایل‌ها | اگر CSS/JS در صفحه‌ساز بارگذاری نمی‌شود، این را فعال کنید |

## ویرایش برگه ZSA Studio (مهم‌ترین مرحله)

برگه را در ویرایشگر باز کنید و بلوک «HTML سفارشی» فعلی را ببینید. **هیچ بخشی را از صفر نمی‌نویسید**؛ فقط کارت‌های تکراری را حذف و شورت‌کد می‌گذارید. بهتر است قبل از شروع یک نسخه پشتیبان از کد HTML بردارید.
شورت‌کدها را می‌توانید همان داخل بلوک HTML سفارشی (دقیقاً جای کارت‌ها) تایپ کنید؛ لازم نیست برگه را به چند بلوک تقسیم کنید.

| بخش در کد فعلی | کار |
|---|---|
| دو بلوک `<script type="application/ld+json">` بالای کد (Organization و MobileApplication) | **حذف** — افزونه خودش Schema کامل می‌سازد (وگرنه Organization تکراری ثبت می‌شود) |
| نوار پیشرفت، دکمه تلگرام شناور ✈️ و دکمه بازگشت به بالا ↑ | **بماند** |
| هیرو («استودیو ZSA — خالق تجربه‌های دیجیتال» و دو دکمه) | **بماند** |
| نوار متحرک (Game Development … Digital Products) | **بماند** |
| چهار کارت شمارنده (۰ تعهد به کیفیت / پروژه وب فعال / محصول منتشرشده / پروژه در راه) | کارت‌ها **حذف** ← `[zsa_stats]` |
| بخش «درباره ZSA Studio و حسین زارع» + چهار کارت خدمات | **بماند** |
| تیتر «پروژه‌های فعال و منتشرشده» و زیرتیتر | **بماند** |
| شش کارت پروژه (اکوسیستم، واژیک، واژیک ۲، ماه بانو، یادمان، تراز) | **حذف** ← `[zsa_projects columns="2"]` |
| بنر «نمونه‌کارهای طراحی وب … مشاهده همه ↓» | **بماند** |
| تیتر «نمونه‌کارهای طراحی وب‌سایت» و زیرتیتر | **بماند** |
| هشت کارت مرورگری وب‌سایت | **حذف** ← `[zsa_web_portfolio columns="4"]` |
| دکمه «مشاهده رزومه کامل حسین زارع» | **بماند** |
| تیتر «پروژه‌های در دست توسعه» و زیرتیتر | **بماند** |
| شش کارت «در توسعه» | **حذف** ← `[zsa_coming_soon]` |
| بخش «آماده شروع یک پروژه جدید هستید؟» و شماره تماس | **بماند** |
| خط «تمامی حقوق محفوظ … طراحی و توسعه توسط حسین زارع» | **حذف** (افزونه کردیت را خودکار در پایین صفحه می‌گذارد) — یا در تنظیمات «کردیت پایین صفحه» را خاموش کنید |
| اسکریپت پایین کد (نوار پیشرفت و دکمه بالا) | **بماند** (بخش شمارنده قدیمی بی‌اثر می‌شود و مشکلی ایجاد نمی‌کند) |

نکته: عنصرهایی که `id` دارند (برای لینک دکمه‌های هیرو، مثل «مشاهده پروژه‌ها») را نگه دارید و فقط **محتوای داخل گرید** را با شورت‌کد عوض کنید.

### شورت‌کدها

#### شورت‌کد سراسری (پیشنهادی برای برگهٔ تمام‌صفحه)

```
[zsa_portfolio]
[zsa_portfolio sections="projects,web,soon" columns="2" web_columns="4" limit="0"]
[zsa_portfolio fullpage="1"]
```

| ویژگی | پیش‌فرض | معنی |
|---|---|---|
| `sections` | `hero,stats,projects,web,soon,cta` | بخش‌هایی که چاپ می‌شوند (با کاما جدا کنید) |
| `type` | خالی (همهٔ غیر وب‌سایت‌ها) | محدود کردن پروژه‌ها به نوع/انواع خاص |
| `limit` | `0` (همه) | بیشینهٔ تعداد پروژه در هر بخش |
| `columns` | از تنظیمات | ستون‌های بخش «پروژه‌ها» |
| `web_columns` | از تنظیمات | ستون‌های بخش «نمونه‌کارهای وب» |
| `fullpage` | `0` | `1` = فعال‌کردن حالت حذف عناصر قالب با CSS |

> متن‌های هیرو، تیتر بخش‌ها و CTA از **تنظیمات ← تب «متن‌ها»** تغییر می‌کنند؛ نیازی به ویرایش کد نیست.

#### شورت‌کدهای بخش‌بخش (اگر می‌خواهید برگه را خودتان بچینید)

```
[zsa_stats]
[zsa_projects type="app,game,ecosystem" limit="0" columns="2"]
[zsa_web_portfolio limit="0" columns="4"]
[zsa_coming_soon limit="0"]
[zsa_credit]
```

- `limit="0"` یعنی همه. `type` اختیاری است (پیش‌فرض: همه غیر وب‌سایت‌ها).
- `[zsa_credit]` کردیت را در جای دلخواه می‌گذارد (اگر استفاده شود، چاپ خودکار تکرار نمی‌شود).
- بلوک گوتنبرگ «پورتفولیو ZSA» پنج حالت دارد: پروژه‌ها، نمونه‌کارهای وب، در‌توسعه، آمار و **صفحهٔ کامل**.

## سئو — چه چیزی خودکار است و چه چیزی با شماست

**خودکار:**
- JSON-LD یکپارچه (`@graph`): Organization، CollectionPage، ItemList، BreadcrumbList، و برای هر پروژه MobileApplication / SoftwareApplication / WebSite.
- صفحه تکی هر اپلیکیشن/بازی (`/project/نام/`) با مسیر صفحه، توضیح، پلتفرم‌ها، دکمه‌ها، لینک به سایر پروژه‌ها و متا/Open Graph (اگر افزونه سئوی دیگری فعال نباشد).
- کارت‌ها به صفحه تکی لینک می‌دهند (لینک‌سازی داخلی) و هدینگ‌ها پشت سر هم‌اند (تیتر بخش `h2` ← کارت `h3`).
- صفحه‌های نازک (پروژه‌های وب‌سایت، «در توسعه» و بایگانی نوع پروژه) `noindex` می‌شوند و از sitemap اصلی وردپرس (`/wp-sitemap.xml`) حذف می‌شوند.

**با شماست (بیشترین اثر را همین‌ها دارند):**
1. در ویرایشگر **هر اپلیکیشن/بازی** یک توضیح واقعی و کامل (حداقل ۳۰۰ کلمه: امکانات، نحوه استفاده، سؤالات رایج) بنویسید. متن صفحه تکی همان است.
2. برای **تصویر شاخص** هر پروژه «متن جایگزین» (alt) بنویسید.
3. برای خود برگه ZSA Studio یک **عنوان سئو و توضیحات متا** یکتا تنظیم کنید (با افزونه سئوی سایت).
4. `https://kafezare.ir/wp-sitemap.xml` را در Google Search Console ثبت کنید و پس از انتشار، صفحه را در «Request indexing» بدهید.
5. از صفحه‌های دیگر سایت (مثلاً مقاله‌ها و صفحه کافه زارع) به صفحه‌های اپلیکیشن‌ها لینک بدهید.

> هیچ افزونه‌ای نتیجه «اول گوگل» را تضمین نمی‌کند؛ این افزونه پایه فنی سئو را درست و تمیز می‌کند.
> نکته درباره نمایش ستاره/امتیاز: گوگل برای نتیجه‌های غنی اپلیکیشن، امتیاز یا نقد واقعی می‌خواهد. افزونه عمداً امتیاز نمی‌سازد؛ فقط وقتی امتیاز واقعی دارید اضافه کنید.

## کش

- همه‌چیز در یک ترانزینت یک‌ساعته (`zsa_pm_dataset_v3`) ذخیره می‌شود؛ با کش گرم، هر صفحه فقط همان یک ترانزینت را می‌خواند.
- با ذخیره/حذف/زباله‌دان‌کردن/خروج از زباله‌دان یک پروژه یا تغییر ترم‌های «نوع پروژه»، کش افزونه و کش WP Fastest Cache / LiteSpeed پاک می‌شود (نه با هر ویرایش نوشته‌های دیگر سایت).
- اگر کش شیء خارجی (Redis/Memcached) دارید، پاک‌سازی دستی کلیدهای شناخته‌شده را هم مستقیم حذف می‌کند.

## امنیت

nonce در متاباکس‌ها و همه AJAXها، بررسی دسترسی، پاکسازی ورودی‌ها و escape خروجی‌ها، `defined('ABSPATH')` در همه فایل‌ها، ورودی JSON فقط با کلیدهای مجاز و پاکسازی‌شده.

## تغییرات نسخه ۱.۱.۰

**جدید**
- شورت‌کد سراسری `[zsa_portfolio]` (هیرو + آمار + پروژه‌ها + وب + در‌توسعه + CTA).
- قالب برگهٔ «ZSA — تمام‌صفحه (بدون هدر/فوتر)» و حالت سازگار CSS برای صفحه‌سازها.
- دو تب تنظیمات «تمام‌صفحه» و «متن‌ها».
- حالت «صفحهٔ کامل» در بلوک گوتنبرگ + استایل پیش‌نمایش ویرایشگر.

**رفع اشکال**
- محدودیت پنهان ۱۰۰ پروژه در مجموعه‌داده.
- پاک‌نشدن کش هنگام حذف پروژه (`deleted_post` هیچ‌وقت صدا نمی‌شد) و هنگام تغییر ترم‌ها.
- پاک‌نشدن کش شیء خارجی هنگام پاک‌سازی دستی.
- تداخل فیلتر «ترتیب» و «وضعیت» در لیست مدیریت.
- بازنویسی مقادیر مشروع صفر/خالی در متاباکس‌ها هنگام ذخیره.
- CSS نامعتبر `repeat(min(...))` که کل قانون گرید را بی‌اثر می‌کرد.
- ویرایش سریع در لیست مدیریت اصلاً کار نمی‌کرد.
- نبود تصویر شاخص در صفحه تکی پروژه، متغیر تعریف‌نشده در کارت وب، نبود `rel="noopener noreferrer"`.
- فلاش شدن پیوندهای یکتا در هر بارگیری سایت هنگام ارتقا.

**بهبود**
- کلید کش `v3`؛ تصاویر با `srcset`/`sizes`؛ متن جایگزین خودکار تصاویر مهاجرت؛ خوانایی کارت‌ها روی قالب‌های روشن.
